# PRD - 소닉 애니메이션 뷰어

## 1. 개요

`sonic-sprite.png` 스프라이트 시트에 들어있는 소닉의 모든 동작을 차례대로 재생해 보여주는 pico2d 프로그램.

| 항목 | 내용 |
|---|---|
| 소스 | `Labs/LEC09/sonic_animation_viewer.py` (단일 파일) |
| 리소스 | `Labs/LEC09/sonic-sprite.png` |
| 라이브러리 | pico2d |
| 실행 | `Labs/LEC09` 폴더에서 `python sonic_animation_viewer.py` |

## 2. 요구사항

| ID | 요구사항 | 구현 기준 |
|---|---|---|
| R1 | 시트의 모든 동작을 재생 | 4절의 16개 동작(프레임 76개)을 전부 재생 |
| R2 | 한 동작을 5번 반복 | `LOOP_COUNT = 5` |
| R3 | 동작 사이에 1초 쉼 | `PAUSE_TIME = 1.0`, 마지막 프레임을 화면에 유지한 채 정지 |
| R4 | 끝나면 처음부터 무한 반복 | 16번째 동작 후 1번째 동작으로 복귀 |
| R5 | 충분히 확대해서 표시 | 800x600 캔버스에 8배 확대 (`SCALE = 8`) |
| R6 | 단계별 개발, 커밋 20개 이상 | 7절의 커밋 계획(29개)을 따름 |
| R7 | 종료 (PRE-PRD에는 없으나 필요) | ESC 또는 창 닫기, 정지 시간 중에도 즉시 반응 |

## 3. 스프라이트 시트 분석

- 크기 399 x 525, **배경은 이미 투명**(알파 0) → 컬러키 처리 없이 `load_image()`로 바로 사용
- 소닉 프레임은 10개 행에 총 76개. 크기가 20~40 x 26~45px로 제각각이고 간격도 일정하지 않아 **격자 분할 불가 → 프레임별 좌표를 표로 관리**
- 맨 위 제목 글자, 맨 아래 크레딧 글자, 그 옆 다른 캐릭터 2개(노란색/갈색, 각 1프레임)는 애니메이션이 아니므로 제외

## 4. 애니메이션 목록과 프레임 좌표

| 14 | board | 9 | 5 | 0.1 | 빨간 판을 들고 달리기 |

- 위 delay 기준으로 전체 한 바퀴는 약 60초(재생 44초 + 정지 16초)다.
- 동작 이름, 같은 행 안에서 동작을 나눈 경계(idle/look_up/crouch, run/skid, turn/tumble, push/board, shock/wag), 2행 12개를 walk 하나로 묶은 것은 그림만 보고 정한 것이다. 재생해 보고 어색하면 바꾼다.
- dash와 peel_out의 앞 2프레임은 출발 자세, 뒤 4프레임이 질주다. 5회 반복 때 출발 자세가 매번 끼어 어색하면 뒤 4프레임만 반복하도록 바꾼다.
- delay는 초기값이며 6단계에서 눈으로 보며 조정한다.

## 5. 화면과 그리기 규칙

| 상수 | 값 | 의미 |
|---|---|---|
| `CANVAS_W, CANVAS_H` | 800, 600 | 캔버스 크기 |
| `SCALE` | 8 | 확대 배율 (가장 큰 프레임 45px → 360px, 화면 높이의 60%) |
| `GROUND_Y` | 120 | 발이 닿는 바닥선의 화면 y좌표 |
| `LOOP_COUNT` | 5 | 동작별 반복 횟수 |
| `PAUSE_TIME` | 1.0 | 동작 사이 정지 시간(초) |

- **가로**: 화면 가로 중앙에 프레임 중앙을 맞춘다.
- **세로**: 동작마다 프레임들의 가장 낮은 `bottom`을 기준선(`base`)으로 삼아 바닥선에 맞추고, 각 프레임은 시트에서 기준선보다 떠 있는 만큼(`b - base`) 그대로 띄운다. 걷기에서 발이 살짝 들리는 것 같은 시트의 높이 차이가 유지된다.
- 그리기 좌표: `x = CANVAS_W//2 - w*SCALE//2`, `y = GROUND_Y + (b - base)*SCALE`
- 그리기 호출: `sheet.clip_draw_to_origin(l, b, w, h, x, y, w*SCALE, h*SCALE)`

## 6. 코드 구조

```python
# 상수 (5절)
# ANIMATIONS = [{'name': 'idle', 'delay': 0.15, 'frames': [...]}, ...]   (4절)

def handle_events():          # SDL_QUIT, ESC → running = False
def draw_frame(frame, base):  # clear → 5절 규칙으로 확대 출력 → update
def wait(seconds):            # 0.05초씩 끊어 쉬면서 handle_events 호출
def play(anim):               # base 계산 → LOOP_COUNT번 반복 재생 → wait(PAUSE_TIME)

open_canvas(CANVAS_W, CANVAS_H)
sheet = load_image('sonic-sprite.png')
running = True
while running:                # R4 무한 반복
    for anim in ANIMATIONS:
        if not running: break
        play(anim)
close_canvas()
```

- `play()`는 프레임마다 `handle_events → draw_frame → delay(anim['delay'])` 순으로 돌고, `running`이 꺼지면 즉시 빠져나온다.
- 전역 변수는 `running`, `sheet` 두 개만 사용한다.

## 7. 개발 단계와 커밋 계획

### 7.1 진행 규칙

- 브랜치: `lec09-animation-viewer` (작업 전 이 문서들을 먼저 커밋해 두고, 아래 번호는 소스 커밋만 센다)
- 한 커밋에는 한 가지 변경만 담는다. 커밋 대상 파일은 `sonic_animation_viewer.py` 하나다.
- 매 커밋 전에 직접 실행해서 "확인" 칸의 내용을 눈으로 본 뒤 커밋한다. 모든 커밋은 오류 없이 실행되고 ESC로 종료되는 상태여야 한다(1번 제외).
- 커밋 메시지는 아래 표의 문구를 기본으로 하되, 실제 변경과 다르면 맞게 고친다.
- 한 단계가 끝날 때마다 8절의 완료 기준 중 해당 항목을 점검한다.

### 7.2 1단계 - 뼈대 (커밋 1~3)

목표: 창이 뜨고, 시트가 보이고, 정상 종료된다.

| # | 커밋 메시지 | 작업 내용 | 확인 |
|---|---|---|---|
| 1 | 캔버스를 여는 최소 프로그램 작성 | `open_canvas(800, 600)` → `delay(2)` → `close_canvas()` | 빈 창이 2초 떴다 닫힌다 |
| 2 | 메인 루프와 종료 처리 추가 | `running` 변수, `handle_events()`(SDL_QUIT, ESC), `while running` 루프 | 창이 유지되고 ESC·창 닫기로 종료된다 |
| 3 | 스프라이트 시트 로드 및 원본 출력 | `load_image('sonic-sprite.png')`, 화면 중앙에 시트 전체를 1배로 그림 | 시트 전체가 투명 배경으로 보인다 |

### 7.3 2단계 - 프레임 한 개 출력 (커밋 4~6)

목표: 프레임 하나를 잘라 정해진 위치에 확대해서 그린다.

| # | 커밋 메시지 | 작업 내용 | 확인 |
|---|---|---|---|
| 4 | 화면 상수 정의 | `CANVAS_W`, `CANVAS_H`, `SCALE`, `GROUND_Y`를 선언하고 `open_canvas`에 적용 | 동작은 3번과 같다 |
| 5 | idle 첫 프레임을 잘라 확대 출력 | 시트 전체 출력을 지우고 `(1,447,29,39)`를 `clip_draw_to_origin`으로 8배 출력 | 서 있는 소닉 한 개가 크게, 옆 프레임 없이 보인다 |
| 6 | draw_frame 함수로 분리하고 중앙·바닥 정렬 | `draw_frame(frame, base)` 작성, 5절의 좌표 식 적용 | 소닉이 가로 중앙, 바닥선 위에 선다 |

### 7.4 3단계 - 동작 한 개 재생 (커밋 7~8)

목표: idle 하나가 끊김 없이 돌아간다.

| # | 커밋 메시지 | 작업 내용 | 확인 |
|---|---|---|---|
| 7 | idle 프레임 좌표 추가 및 순환 재생 | idle 7프레임 리스트, 루프에서 차례로 `draw_frame` + `delay(0.15)` | 눈 깜빡임과 발 구르기가 반복된다 |
| 8 | ANIMATIONS 구조와 play 함수 도입 | `ANIMATIONS = [{'name','delay','frames'}]`에 idle 등록, `play(anim)`이 `base` 계산 후 한 번 재생 | 화면은 7번과 같다 |

### 7.5 4단계 - 재생 규칙 (커밋 9~11)

목표: R2, R3, R4를 idle 하나로 완성한다. 이후에는 데이터만 추가하면 된다.

| # | 커밋 메시지 | 작업 내용 | 확인 |
|---|---|---|---|
| 9 | 동작을 5회 반복 재생 | `LOOP_COUNT = 5`, `play()`에 반복 추가, 프레임마다 `running` 검사 | idle이 5번 돈 것을 세어 확인한다 |
| 10 | 동작 사이 1초 정지 추가 | `PAUSE_TIME = 1.0`, `wait()` 작성, `play()` 끝에서 호출 | 5회 후 마지막 프레임에서 1초 멈추고, 멈춘 동안 ESC가 바로 먹는다 |
| 11 | 전체 동작 순회와 무한 반복 | `while running:` 안에서 `for anim in ANIMATIONS` 순회, 종료 시 즉시 탈출 | idle 5회 → 1초 정지가 계속 되풀이된다 |

### 7.6 5단계 - 동작 추가 (커밋 12~26)

목표: R1 완성. 한 커밋에 동작 하나만 `ANIMATIONS` 끝에 추가한다. 좌표와 delay는 4절의 값을 쓴다.

확인을 빠르게 하려면 작업 중에만 `ANIMATIONS[-1:]`로 새 동작만 재생해 보고, **커밋 전에 전체 재생으로 되돌린다.**

| # | 커밋 메시지 | 프레임 | 특히 볼 것 |
|---|---|---|---|
| 12 | look_up 동작 추가 | 2 | 왼쪽에 앞 프레임(idle)의 신발 끝이 섞이지 않는지 |
| 13 | crouch 동작 추가 | 2 | 키가 줄어도 발이 바닥선에 붙어 있는지 |
| 14 | walk 동작 추가 | 12 | 12프레임이 한 걸음 주기로 자연스럽게 이어지는지 (어색하면 둘로 나눔) |
| 15 | run 동작 추가 | 4 | 좌우로 튀지 않는지 |
| 16 | skid 동작 추가 | 2 | 빨간 먼지 효과가 잘리지 않는지 |
| 17 | spin 동작 추가 | 9 | 회전 중 위아래로 덜컹거리지 않는지, 마지막 공 프레임이 어울리는지 |
| 18 | spin_dash 동작 추가 | 6 | 공이 제자리에서 도는지 |
| 19 | dash 동작 추가 | 6 | 앞 2프레임(출발 자세)이 반복에 끼어 어색한지 |
| 20 | peel_out 동작 추가 | 6 | 폭이 30 → 39px로 넓어질 때 몸통이 밀리는지 |
| 21 | turn 동작 추가 | 6 | 한 바퀴 도는 순서가 맞는지 |
| 22 | tumble 동작 추가 | 2 | turn과 분리한 것이 맞는지 |
| 23 | push 동작 추가 | 3 | 첫 프레임이 나머지와 같은 동작인지 |

### 7.7 6단계 - 다듬기 (커밋 27~29)

목표: 전체를 한 바퀴(약 60초) 돌려 보며 어색한 곳을 고친다.

| # | 커밋 메시지 | 작업 내용 | 확인 |
|---|---|---|---|
| 27 | 동작별 재생 속도 조정 | 전체 재생을 보며 너무 빠르거나 느린 동작의 `delay` 수정 | 2프레임 동작도 알아볼 수 있는 속도다 |
| 28 | 프레임 좌우 떨림 보정 | 떨림이 눈에 띄는 동작만 프레임에 가로 보정값(dx)을 추가 | 몸통이 제자리에 있고 팔다리만 움직인다 |
| 29 | 주석 정리 | 프레임 데이터 형식, 정렬 규칙, 상수 의미를 주석으로 정리 | 실행 결과는 28번과 같다 |
